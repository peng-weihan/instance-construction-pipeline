# Source and selection card

- Official repository: https://github.com/toml-rs/toml ; fixed commit `ceac6e4412420d5a5c19e4f7293ad005cf1a31b2`. The GitHub commit response is saved in `authoring/sources/commit.json`; complete official codeload archive and extracted workspace are retained. License is MIT OR Apache-2.0; original root and crate licenses remain in starter/reference bundles, dependency licenses remain in vendor.
- Real subsystem: `crates/toml_parser/src/decoder/string.rs` decodes TOML 1.1 strings with source-relative errors; `crates/toml_edit/src/encode.rs` joins raw representation/decor with canonical fallback; `crates/toml_writer/src/string.rs` chooses and emits key/value delimiters and escapes. `toml`, `toml_edit`, `toml_parser`, and `toml_writer` are actual path-dependent production crates, not a replacement parser.
- Transformation: four complete function implementations (264 source lines total) are replaced by compiling semantic regressions in three files. `authoring/mask-manifest.json` identifies exact boundaries and original segment hashes. `solution/restore.patch` is the inverse; full reference workspace is separately private in `solution/reference.tar.gz`. Original upstream unit/integration/compliance tests and full source remain in starter, including their documentation and licenses. No upstream implementation is relabeled as an original author solution.
- Strong starting point: the genuine complete upstream implementation is a runnable strong reference. The public starter keeps the lexer, AST, error infrastructure, hex scalar decoder, container edits, TOML types, and native tests. Copying upstream's four functions is a direct public-source shortcut if network/source recall is available. This is substantial contamination/early-saturation risk; source volume and build latency are not difficulty evidence.
- Remaining paths after two hours (hypotheses, not measurements): (1) completing recovery and exact byte-span diagnostics across malformed Unicode and line folds; (2) preserving original raw text/decor during nested and array edits while routing new values through safe writer encodings. These paths are coupled by reparse/roundtrip tests but may be solved much faster by source recall.
- Cheapest falsification: run unmodified starter, inverse/reference, and two partial restorations against the same frozen cases; then a short permitted frontier-model pilot would test saturation before any six-hour budget. No model pilot is run in this batch.
- Evidence: reference outputs are frozen from the pinned upstream build; Python 3.12 tomllib independently checks applicable TOML 1.0 input semantics. TOML 1.1-only features and exact formatting/error text rely on pinned upstream and the ABNF/comments in its decoder. Seven group denominators remain fixed. This is bounded behavioral coverage, not a proof of full TOML compatibility.
- Decision: `hold_current_profile_for_long_horizon`, with `difficulty_high_risk` as a design-screening hypothesis. The gaps concern a narrow string-handling slice while the tokenizer, parser state machine, AST, and container edit machinery remain intact. That limited restoration scope and public-source recall/copy risk justify low priority before spending six hours. The private inverse patch is author construction evidence, not a solver-accessible shortcut; its host full score does not measure solver effort. Line/function counts alone do not establish difficulty or early saturation. No public simple baseline has been measured at full score. A separately versioned broader tokenizer/parser and edit-state recovery profile could be considered in a future round. Keep this version as a working host construction/scorer pilot. Runtime packaging remains `hold_for_evidence`: Docker/Harbor isolation, dual-platform images, final package audit, six-hour difficulty, and growth are not verified. Do not count it as an accepted six-hour instance.
