# Restore TOML string handling across parser, editor, and serializer

Repair the real toml-rs/toml workspace in `/home/workspace/toml-string-recovery/submission/`. It is fixed at `ceac6e4412420d5a5c19e4f7293ad005cf1a31b2` and implements TOML 1.1. Four recovery gaps affect three production files: basic-string escape decoding, multiline basic-string line folding, formatting of editable scalar values, and writing strings/keys. The starter compiles but these paths regress. Restore the behavior of the fixed version while preserving the public Rust APIs, feature declarations, ordinary non-string TOML behavior, and error semantics.

The parser must decode all supported basic escapes, including `\e`, `\xHH`, `\uHHHH`, and `\UHHHHHHHH`; reject malformed digits, surrogate code points, and out-of-range values; and report the fixed version's message and byte span. Multiline folding consumes the required newline and following whitespace/newlines, supports CRLF, and preserves literal-string content. An unchanged `DocumentMut` must preserve original spelling, quotes, whitespace, and comments according to the fixed upstream behavior (which normalizes CRLF output to LF). Edits through the normal `Item` API must change the requested value while preserving other document content. Generated values and quoted keys must use the fixed serializer's safe string encoding and must reparse to the same semantic value.

Submit the complete editable workspace under `submission/`, including `Cargo.toml` and `crates/`. All scored files are in that directory. Do not replace the probe, vendor tree, grader, or Rust compiler: the judge supplies its own probe and builds your crates as path dependencies. You may change any implementation files in the workspace. Keep licenses, package identities, public API signatures, and feature behavior. No new external dependencies are available at runtime; the provided vendor closure supports the probe and current production dependencies. The full original upstream tests remain as development material; their additional dev dependencies are not all vendored.

The public probe at `/opt/devprobe` exercises real `toml`, `toml_parser`, `toml_edit`, and `toml_writer` crate paths. Build it with `cargo build --offline --locked --manifest-path /opt/devprobe/Cargo.toml --jobs 2`. Pipe JSON lines from `/opt/dev-cases.json` request fields into `/opt/devprobe/target/debug/edgebench-toml-probe`. Its operations are `roundtrip`, `edit`, `serialize`, and `diagnostic`. `edit.changes` uses a path of string table keys or integer array indexes and a JSON replacement value. Public cases include expected outputs. Original native Rust tests are also retained for inspection and local tests if their dependencies are present.

Scoring uses 35 fixed behavioral cases in seven equally weighted capability groups: decoding, multiline strings, document formatting, edits, serialization, diagnostics, and integration. Each group's score is its passed-case fraction; reward is the mean of the seven group scores. Duplicate cases do not change group weight. Exact formatting, semantics, or diagnostic message/span are compared according to each operation. Compile errors, crashes, missing source, wrong results, and candidate timeouts receive valid partial/zero scores. An unavailable promised compiler/dependency or broken judge is an invalid evaluation. The judge compiles the supplied probe with your crate sources offline (two jobs, 120 seconds) and runs each request in a separate process (three seconds). It does not score source text or fingerprints. The agent budget is 21600 seconds; feedback and final selection use submission file snapshots and best valid score.
