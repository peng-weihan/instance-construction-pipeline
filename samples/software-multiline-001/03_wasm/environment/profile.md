# Exact supported profile

Normative source: WebAssembly/spec, fixed revision d910f03bd6d6477656fc5070b5098e8f909305d3 (v1.0.0). Public normative documents and their original notices are in `specification/`. This exercise is a bounded i32 profile, not a claim of full conformance.

Input modules use version-1 binary encoding. The following sections are in scope: custom (ignored), type, function, memory, export, code, data. Imports, start, tables, elements and globals are out of scope. One optional memory has 0–16 pages, with an explicit maximum no larger than 16 or an effective maximum of 16 when absent. Active data segment memory index is zero, initialized using i32.const expressions. Every function accepts zero or more i32 parameters and returns zero or one i32 value. Block signatures are void or i32, with no block parameters. All executable modules are well typed; general validation and invalid type programs are not evaluated. Malformed cases only cover magic/version, truncated LEB/section payload, and inconsistent section length. Data, code and custom sections retain standard binary framing. Five-byte i32 LEB128 and function/type indices use normal Wasm encoding.

Instructions: unreachable, nop, block, loop, if/else, end, br, br_if, br_table, return, call, drop, select, local.get/set/tee, i32.const, i32.eqz, i32.eq/ne/lt_s/lt_u/gt_s/gt_u/le_s/le_u/ge_s/ge_u, i32.clz/ctz/popcnt, i32.add/sub/mul/div_s/div_u/rem_s/rem_u/and/or/xor/shl/shr_s/shr_u/rotl/rotr, i32.load, i32.load8_s/u, i32.load16_s/u, i32.store/store8/store16, memory.size and memory.grow. Memarg offset and alignment are encoded normally; alignment does not impose runtime address alignment. Call depth is at most 64 and executed instructions per request are below 100000 in evaluated programs. Host-defined recursion exhaustion and fuel policies outside those bounds are not compared.

Arithmetic wraps modulo 2^32; shifts mask the amount to five bits. Signed division truncates toward zero; zero divisors and signed division overflow trap. Signed remainder of INT_MIN by -1 is zero. Branch labels count outward, loop labels branch to the beginning, and block labels carry the result type. Function calls have fresh locals and operand stacks. Memory is little endian, and out-of-bounds access traps before a write. memory.grow returns the previous page count or -1 without modifying memory on failure. Calls in one request share memory and growth. Observations always refer to a valid in-bounds interval of an exported memory named `memory`.

JSON requests are syntactically valid, contain at most one module, and use declared function exports with correctly typed argument counts. This is a bytecode execution implementation exercise, not a requirement to parse WAT. `dev_cases.json` includes actual binary modules and WAT explanations for development; hidden cases provide binary only to the candidate process.
