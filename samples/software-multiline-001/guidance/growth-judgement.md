# 从曲线判断真实持续改进

先确认本轮标准。下述数值为用户2026-10-14最后确认的当前批次，而非EdgeBench通用官方门槛；用户另改时替换本轮配置。

## 统一口径

对第i条，`S_i(t)`是截至实际学习t小时**有效、完成评分的快照**的最好原始分。按快照采集时间，记录反馈到达时间；待判分、评分器异常、缺奖励均不补0。取最好提交，不把最终源码与历史最好分错配。若最终快照在停止后收取，须有停止/冻结证据才能按实际学习截止归属，不靠文件mtime猜测。

`M(t) = (S_1(t)+S_2(t)+S_3(t))/3`。

当前后续增长：`G=(M(6)-M(2))/M(2) >=0.10`，等价`M(6)>=1.10*M(2)`。不是“2h到0.10”、不是加0.10、不是加5分、不是三个相对增长率的平均，也不要求每条都增长10%。首小时门槛是从真实起点的均分增长不超过0.50；本批NOP/公开起点为0。完整做出时间另按题目真实完成条件检查；优化题pass_rate=1仅表示合法，不表示达最优。

M(2)=0时相对增长未定义。不能加epsilon、默认100%或自动通过；报告绝对增长和有效点，明确缺少这一口径的解释。未满2h的副本不要提前固定S(2)，未满6h不输出最终均分通过。

每条保留原始分数、原始指标/具名维度、快照/源码SHA、评分器和环境身份；三条统一公式、数据、权重和分母。当前用户取消了事后映射，不为美观把历史分乘2或改reward。新评分修订必须独立版本，不能挪旧模型所见反馈。

## 看“还有东西可学”

好的预测指向具体工作：难的基础结构尚未解决；至少两种有依据的后期算法/模型/证明路径；局部反馈能区分这些方向；更高强解实际可达；改进能保存为成果。一个算法完全解决下一阶段，后面只是批量运行，可能很快饱和。

实际观察写1/2/3/5/6h节点及最好曲线，同时画每次原分。多次有意义的中后期提高，比只在终点勉强过线更有说服力；这是设计偏好，不擅自新增每小时都增长的硬门槛。若只有最后一次跳升，报告真实形态和原因。

| 观察 | 判断与下一步 |
| --- | --- |
| 早期完整做出，或首小时过快 | 原问题/派生部分太容易；检查已有定理、脚本、廉价参数放大等，不补无关题量 |
| 1h可起步、2h后仍有多条可验证改进、晚期成果更好 | 可继续/补副本，最终仍需三条均分与质检 |
| 健康工作但长期全0 | 可能太难、部分分太稀或反馈/目标不闭合；先定位，不奖励准备/文档凑分 |
| 两小时后长平台 | 检查饱和、隐藏瓶颈或缺少真实提升空间；强人类素材也可能只剩低增量 |
| 最好分涨，代码/结果未有实质改变 | 重评同一快照；可能是抽样极值而非能力改进 |
| API/沙箱/评分错误，长时间无有效工具 | 此段难度证据不成立；分类恢复/重测，不称模型做不出 |

## 稳定性是增长判断的一部分

交付要求用固定参考快照五次和跨架构证据，但缓存参考稳定只证明那份参考。付费前检查代表性考生成果；程序执行型任务检查非缓存在线候选，固定结果/Lean型不要求额外在线程序；首条有明显增长时，再独立重放2h与后期成果，先各两次，疑点再扩展，避免无目的重复。

保持相同T/F/I、输入、支持文件、预算和原评分器。分别记录编译source/ELF（能保留时）、实际输出/计划、合法性、原始整数指标、CPU/wall、随机/计时决策。合法低分不是基础设施失败；编译ELF没保留就不能宣称二进制相同。

将同快照极差、历史→重放偏差、配对重放增量与预期提升空间及原曲线增量比较。参考5次不抖、最好分很高，都不能掩盖模型成果的大抖动。噪声足以解释增长时，停止称它为真实学习增益，在新版本修结果/计步/RNG/反馈契约，原数值保留。指标天然有噪声的题按客户条款评估空间和误差，不用自创固定误差阈值判全部题。

重复判分差异要先核验候选/输入/role/资源确实相同。仅源相同、编译选项不同或错误镜像，会产生无关比较；反之不能用“timer可能导致”代替实际重复数据。

列三条1/2/6h最好分、原始总分均值、M(2)、M(6)、绝对/相对增长、实际完成预算、完整解是否过早、独立重放和技术QC状态。只有数值合格写`curve_numeric_pass`；模型身份、六小时真实性、稳定性、来源、跨架构、接收闭包缺一项均不能自动变为`delivery_pass`。

## 用脚本统一计算口径

在本批已审计的history与真实停止记录上运行，不改原文件：

```bash
python3 /ws/users/wcgu/skills/edgebench-task-authoring/scripts/summarize_curves.py \
  --input /absolute/path/curve-input.json --output /absolute/path/curve-summary.json
```

输入为对象，`runs`含三条记录。每条给不同`label`、真实`starting_score`、`learning_stop_path`和`history_segments`；未分段时每段只有`path`且offset为0。history接受条目列表或`{"entries":[...]}`，有效条目必须含`status:"completed"`、`valid:true`、`score`与`snapshot_time_seconds`。停止文件读取`actual_stop_dispatch_elapsed_sec`，计划`learning_window_sec`不算实际预算。

恢复段可显式填`credited_prefix_sec`及`credit_evidence`，原段设`include_until_sec`排除中断尾部，新段设`offset_sec`；该信用须先审计原生会话、预算与制品，脚本不猜测。路径相对输入manifest，也接受绝对路径；输出附输入、history和停止文件SHA。配置可含`criteria:{"budget_sec":21600,"first_hour_gain_max":".50","post2h_relative_min":".10","required_runs":3}`。分数保持原值，Decimal字符串避免边界浮点误差。

结果的`curve_numeric_pass`仅证明该输入的数值及预算算术，不能替代模型身份、独立性、故障影响、重评稳定性和完整交付。脚本错误、缺点和零分母如实处理，不填分补齐。
