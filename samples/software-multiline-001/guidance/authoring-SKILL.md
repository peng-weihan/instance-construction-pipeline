# 从素材判断到三条轨迹交付

目标是产出有真实学习曲线的任务。先判断模型在两小时后还能改进什么，再制作题包、运行标定并交付。国际竞赛或顶刊只是候选来源；人类觉得难、源码很多、参考跑得久，都不能直接证明 GPT-6.1-sol 需要六小时。

用户已给出选题、评测、账号及交付授权时继续完整流程，不停在“题包已准备”。只请求真正缺少的信息；制作 skill 本身不等于授权收费评测。任务负责人与评测负责人可以是同一模型；若已要求分工，每份素材保持明确负责人和独立目录。

## 先确定本轮目标

记录题数、三条轨迹要求、截止时间、模型/推理强度、授权账号/二进制、后端、资源、评分规则和原文路径。用户最新指令优先于旧模板、脚本及历史经验。区分“设计期望”“当前验收门槛”“技术和交付门禁”。

本批最后确认的规则（2026-10-14）：原评分保留，范围0–1；GPT-6.1-sol 每条正式学习21600秒，600秒采样；每题三条独立轨迹，按**三条最好分曲线的均值**判断。首小时涨幅不超过0.50，2–6h相对增长达到2h最好分的10%；六小时内完整做出的题不满足本批未解出要求。详细计算、零分母和噪声处理见 [增长判断](references/growth-judgement.md)。原1h<0.2/3h≈0.4/6h≈0.5是较早设计目标，自动难度早停规则已废弃；不得带入新运行。后续用户改标准时更新本轮规则，不覆盖旧测量。

本批正式需求在 `/ws/users/wcgu/edgebench/dev/requirements/delivery-20261011`；技术依据是实际 Harbor0.23.0 schema和官方 Codex adapter。先读 [交付条款](references/delivery-20261011.md)，缺少的外部材料写未核实，不虚构已通过。

## 1. 筛选素材：先找可改善的硬问题

读 [素材筛选](references/source-selection.md)。优先原始竞赛题、官方数据/引擎、顶刊论文的真实计算或证明项目、公开难题榜；实际读题/论文关键部分、源码和人类解法，固定版本和许可。不要仅摘标题。

为每份素材写一张**难度与增长证据卡**：原问题、最强可运行公开基线、便宜捷径、两个小时后的剩余空间、3–6h至少两种具体可尝试的改进、各阶段产生的可冻结成果、可运行强参考/真实可达分数、评分稳定性、最大未知项和最便宜的验证。时间估计标注为假设，并说明什么观察会推翻它。

分为 `reject / hold_for_evidence / build_pilot`，用证据解释。不用“论文顶刊”“十万行”“每小问至少几小时”替代判断。素材原文和候选卡先落盘给用户检查，不必等所有来源齐备才开始最有希望的一题。

## 2. 设计自然的工作链和评分

读 [素材与评分](references/material-and-scoring.md)。阶段依赖来自问题本身；每阶段交出真实可验的证明、系统、方案、推断或策略。提高质量、扩大实际覆盖、消除瓶颈可以涨分；增加重复文件、无关题量、等待时间和代码行数不能制造难度。

优先让 grader 读取冻结的结果：Lean证明、实例解、网格/排列、模型参数、试卷及校验材料。优化算法在 agent 工作阶段运行，输出结果进入 `submission/`。必须执行策略或预测程序时，公开确定性契约并实测固定输入下的重复输出；CPU/wall timer 决定搜索分支、随机种子或迭代数量会让重评分变成噪声。

固定公开基线B、可行强解/上限证据和公式后再运行模型。正确性、原始指标、实测参考成绩和归一化上限分别报告；参考可低于满分。普通Oracle须达到声明上限，开放优化/研究题走open-solution并交可运行参考及真实得分；详见 [参考与上界](references/reference-anchors.md)。不能将弱参考或空脚本伪装成满分Oracle。当前不做为了曲线好看而改分母、权重或历史分数的映射。

## 3. 做可运行题包并消除廉价故障

读 [题包与路径契约](references/package-contract.md)。使用实际支持的 Harbor字段；工作目录 `/home/workspace/<project>`，全部被评分产物在 `submission/`，work和judge构建上下文平级隔离，私有参考不进入解题镜像。冻结T/F/I及逐文件哈希，在新修订目录返修，已有题面、运行和轨迹保留。

原生reward与周期score来自同一权威值。实际完成Oracle/可运行open参考、NOP、至少两份同输入部分解双入口、必要反例/权限检查；依赖、模板/镜像、工具、资源和公开命令实测。通过TaskConfig或某个静态脚本只证明其覆盖范围。旧检查器不支持当前合法字段时核对真实框架，不通过删除有效字段或放宽评分来凑绿灯。

付费前重放公开强B和有代表性的真实考生提交；需要执行优化/预测/策略程序的题追加非缓存在线候选。冻结结果型任务不需额外制造在线候选；缓存参考五次稳定不足以证明程序类候选稳定。若同快照波动可解释期望增量，先修复或换素材。完整交付还需五次同参考、实际ARM及源码闭包等，按 `/ws/users/wcgu/task-qc/SKILL.md` 分别记录，不用基础准入冒充整包合格。

## 4. 先打一条，验证“后续还能学”

读 [首条到三条](references/three-trace-production.md)，执行 `/ws/users/wcgu/edgebench/dev/skills/edgebench-evaluate-6h/SKILL.md` 的实际官方adapter流程。模型成功工具执行、文件读写和真正会话记录是准入；`--version`、curl或登录成功都不足。明确选择授权账号，不改登录配置或默换二进制；新账号用独立身份准入，新正式轨迹用独立会话和输出目录。

观察1h/2h/3h/6h实际快照、有效分、最好分、API/基础设施状况、代码/成果变化和剩余路径。检查“分在涨、成果是否变好”，重放2h与后期候选，必要时比逐维原始指标。单条高增幅不能冒充最终三条均分通过。

正式评测不设基于难度分数的自动早停。用户明确允许停不合适的观察或出现真实故障时，可结束并标短评测/异常；不将它算满六小时。题目太快、太慢、已平台、噪声主导、环境故障分别处理；只有与真实任务相关的新修订才值得重新标定。

## 5. 在截止时间内补齐三条

串行首条6h再并行后两条，最快也要12h，不能承诺10h。严格10h窗口须预留启动/收尾，后两条必须在 `截止时间−6h−收尾裕量` 前实际开始学习（还需提前完成启动）；使用首条早期真实证据和已验证的剩余空间做风险判断，承认尚未证明完整曲线。若用户优先省成本且时间允许，等首条六小时完成后补两条。不能通过缩短预算、只交一条、复制会话或借旧版本分数解决排期。

三条都收终态、原生模型身份、实际预算、快照/制品/原score绑定和生命周期。按 [增长判断](references/growth-judgement.md) 汇总均分，并独立复核真假增长。原始证据足够时用 `scripts/summarize_curves.py` 计算，脚本仅判断曲线数值，不认证模型、评分质量或交付。

## 6. 交付并保留可复查判断

交付包包含题目、三条真实轨迹、实际评测框架、评分历史/曲线/最佳成果、依赖与构建源码、许可、原始来源和质检报告。用 `/ws/users/wcgu/delivery-qc/skill/SKILL.md` 中适用于本批Harbor任务的条款做真实接收/还原检查，不套用其他项目的Claw双模型/强弱配对门禁；普通文件与包内相对索引闭合，账号凭据不随包。未核实项写明，拒收候选可以给用户审阅但不计合格题数。

输出证据卡、`AUTHORING_REPORT.json`、三轨迹均分表、增长结论和完整交付状态。状态区分素材候选、可跑首条、完整六小时、三条增长通过、交付通过；不能用低分/长期运行证明难，也不能用曲线过线掩盖不确定评分。

真实教训见 [本批案例](references/observed-cases.md)，用于校正判断，不把个案耗时当所有新素材的保证。历史云端安装/路径问题仅在相关后端读取评测skill的云端参考；Docker与阿里云各用实际准入，不互借绿灯。
