# 如何判断素材有六小时改进空间

选择来源的目的，是找到人类已有认真投入且仍有实质改进空间的问题。不是给标题贴难度标签。先取一小批最有希望的来源，完成下列核验再排产。

## 原始材料要读到哪里

竞赛：原题全部约束、官方checker/模拟器、数据规模、排名/公开解法与资源预算。找第一名或强队实现，识别其启发式、参数、特化分支和未解决情境。记录名次出处，不能用GitHub自述冒充已核实排行榜。

论文：问题定义、实验/证明主要瓶颈、补充材料、公开代码和数据、复现实验成本。顶刊论文里的既有脚本一键复现常常很容易；真正有价值的是模型必须设计/验证的剩余部分。先检查输入、许可、离线依赖、硬件，以及能独立核验的预期结果。

Lean：目标陈述与依赖闭包、公开现成证明/目标声明是否能被import、合法axioms及内核验证、自然的中间引理。已在库中证明的目标、可自动化投影的数百小lemma、重命名已有目标都可能几分钟解决。代码行数与编译时长不能代替证明难度。

游戏/模拟：真实动作与状态、引擎版本、公开冠军/强AI、随机种子和结局指标、策略改进是否可保存。默认策略已经接近满分或只要求成功启动，引擎再复杂也不适合。

## 难度证据卡

逐份写出下面内容，连同固定原文和源码落盘：

| 内容 | 必须回答的问题 |
| --- | --- |
| 真实任务 | 最终做出什么？哪个原始约束决定它难？ |
| 强B和捷径 | 最强公开可运行起点是谁？导入已有结果、直接运行、调一个参数、简单集成能到哪里？ |
| 2h后剩余路径 | 起点和常见改进用完后，至少还可尝试哪些独立且有依据的改进？ |
| 工作和反馈 | 每条改进产出什么文件，怎样局部验证，怎样反映到总分？ |
| 可达空间 | 原始指标B、真实强可行解R、公式上界分别是什么？空间是否明显大于误差？ |
| 风险 | 缺参考、未知依赖、噪声、污染、GPU/数据限制、语义checker错误等，哪项能最便宜证伪？ |
| 预测 | 预期阶段/平台区间及原因，哪些观察会使判断失败？这是预测，不是实测。 |
| 决定 | reject / hold_for_evidence / build_pilot，以及证据路径。 |

不要用作者主观“至少几小时”推算模型；估计要拆为需探索的算法/证明/实验次数、单次真实反馈成本和可并行部分。20个可批量一键处理的小题可能比1个有结构耦合的实例容易。

## 最便宜的证伪顺序

1. 实际运行公开默认入口和强B，验证可行输出，检查是否已饱和。
2. 做有限的直接参数扩大、简单集成、常见优化或现成定理检索。如果廉价改动就完整做出，换素材/取更有实质难度的部分。
3. 尝试一个与问题相关的中等参考。完全没有可行partial/反馈，先补可行性，不以持续0分证明难。
4. 固定同一成果重评；若CPU clock搜索、随机/硬件吞吐造成波动，选择结果型提交或实际确定的策略契约。
5. 基本运行闭环后再付费首条，验证早期饱和与后续路径。免费探索不能证明模型耗时，却能淘汰许多不值得六小时的来源。

保留强B，不通过隐藏公开工具、选弱算法、扩大零分阶段、无关工作量或更改归一化假造剩余空间。

## 各类自然改进路径

| 类型 | 能支持长期迭代的真实路径 | 常见假难度 |
| --- | --- | --- |
| 组合优化 | 构造→结构分解→局部搜索→多种邻域/联合优化；大规模耦合的真实实例，提交固定方案 | 只扩大循环次数、隐藏公开冠军实现、把计时波动当改进 |
| 数学 | 关键表示/基础引理→中间结构→难结论；独立正确目标可计部分分 | 已有定理换名、按行数或编译耗时推算证明难度 |
| 科学/ML | 正确数据/物理模型→诊断→更合理估计→跨情境稳健性；固定模型/预测成果 | 一键复现已有结果、数据泄漏、用理论指标上界冒充可达成绩 |
| 金融/系统 | 独立正确性→真实边界/风险约束→优化/再平衡→可复验性能；实例/测试需实质工作 | 大量同构测试、按报告长度计分、只有启动成功检查 |
| 试卷/专业材料 | 平行性、覆盖、难度、答案正确、独立质量复核；多个内容部分有实际独立检查 | 可批量套模板、只查关键词或篇幅、答案不独立验证 |
| 游戏 | 导航/资源/生存→战术→跨种子稳健策略；确定版本/步数/状态，评分不靠在线操作时长 | 挂机积累分数、只延长回合数、默认策略已接近满分 |

每条路线都要写最易的捷径以及为何尚有余地。领域标签本身不构成选择理由。
