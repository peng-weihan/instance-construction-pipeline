# Rebuild the jq stream CLI profile

Implement a reusable jq-compatible command-line program, including parsing and evaluating arbitrary filters inside the profile in `profile.md`. You are building the CLI and evaluation system; submitting a single filter is insufficient.

Save all scored files in `/home/workspace/jq-profile/submission/`. The entry point is `submission/runner.py`, invoked with Python 3.12 followed by jq CLI arguments. It may execute compiled files or load additional code in submission. Normal development tools, dependencies and language choices are allowed. Python and a C/C++ toolchain are available offline. This environment does not ship jq or its implementation; authoring reference binaries and private expected outputs are isolated from the work image. Network access during solving and grading is disabled.

Example: `printf '%s\n' '{"items":[1,2,3]}' | python3 submission/runner.py -c '.items[] | . * 2'` must print three JSON values, 2, 4 and 6, each on its own line. Every input JSON value feeds the filter separately, in input order. Operators can produce streams; array construction collects a stream. Preserve Cartesian binding and lexical scope semantics where specified.

Support `-c`, `-n`, `-s`, `-r`, `-e`, `--arg NAME VALUE`, and `--argjson NAME JSON`. Inputs and output are UTF-8. JSON outputs are compared as ordered value streams with object key order ignored; booleans differ from numbers. With `-r`, string output is compared byte for byte and other values use compact JSON. With `-e`, the last emitted false/null exits 1, an empty stream exits 4, and another last value exits 0. General success exits 0. Syntax or unbound-variable compile failures exit 3; malformed input JSON exits 4; uncaught runtime failures exit 5. Those failures must produce nonempty stderr, but exact diagnostic wording is not scored. Preserve values already printed before an uncaught runtime error.

The target reference is unmodified official jq **1.7.1**, built without the optional regex library. The complete grammar and semantic boundaries are listed in `profile.md`; regex, modules and filesystem features are outside the profile. Public development examples are in `dev_cases.json`; `starter.py` is a small partial evaluator you may extend or replace. Its behavior outside its implemented subset is not a semantic specification.

Eight frozen groups have equal weight 1/8: streams, structure, operators, bindings/functions, control flow, reductions, CLI, and errors. Your total score is the mean of each group's pass fraction; failed, unrun and timed-out cases remain in the denominator. The scorer runs your entry point in a separate process for each invocation with 3 seconds wall time, 2 CPU seconds, Linux address-space limit 512 MiB and output-file limit 1 MiB. Only file snapshots under submission are evaluated. The reference executable and hidden fixtures cannot be used by the candidate process.
