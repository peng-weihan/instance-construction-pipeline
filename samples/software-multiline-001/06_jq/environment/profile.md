# jq 1.7.1 profile

Normative source is official jqlang/jq at full commit 71c2ab509a8628dbbad4bc7b3f98a64aa90d3297 (jq-1.7.1). The original manual and license notices are included under `manual/`. Required behavior is that version's semantics for the following features, including their composition; no fixed list of filter strings is the API.

Values: JSON null/boolean/number/string/array/object. Numeric workloads use ordinary finite values within IEEE754 exact integer range; decimal formatting, NaN, infinity, negative zero, large integer lexemes, Unicode normalization and locale-sensitive behavior are outside scope. Object key order is not scored, but value-stream order is. JSON whitespace is arbitrary. Identifiers and quoted object keys use ordinary jq syntax.

Grammar and primitives: literals, identity `.`, field and nested field access, constant signed array indices and slices, iteration `.[]`, optional access `?`, pipe, comma, parentheses, arrays and object construction, arithmetic + - * / %, overloaded array/string/object addition and recursive object multiplication, equality/comparisons, and/or/not, `//`, lexical `$variables` and `as` binding including array/object destructuring, `def` with filter parameters and recursive calls, if/then/elif/else/end, select, try/catch, error, label/break, reduce and foreach with update and extraction, assignment `=` and `|=` and arithmetic updates. This is a compositional filter language profile, not only the public sample programs.

Builtins in scope: empty, inputs, range, limit, until, while, recurse/`..`, numbers, scalars, type, length, keys, has, map, add, flatten, any/all, min_by/max_by, sort/unique/sort_by/group_by, getpath, paths, del, to_entries/from_entries, ascii_upcase and split. Truthiness follows jq: only false and null are false. `//` filters false/null; numerical zero and empty collections remain truthy. Empty streams interact with generators and object/array construction according to jq, and variables retain their original input where the manual specifies it. Operators and function parameters are filters and can emit multiple values. User-defined recursion is finite on the scored inputs.

CLI flags are -c, -n, -s, -r, -e, --arg and --argjson. stdin can contain zero or more concatenated JSON values separated by whitespace; -n supplies one null input without consuming JSON values, -s collects all input values into one array, and inputs consumes the remaining values. No input filenames, -f, modules, regular expressions, time/date, environment access, random sources, raw-input parsing or `--stream` parser events are required. The word stream here means jq's output value stream and stdin-value stream; it does not imply `--stream` support.

Errors are classified by exit status and nonempty stderr rather than exact wording. A runtime error can follow successful output and must preserve that prefix. Compile errors are detected even if no input values are present. Invalid stdin JSON is a parse failure. Behavior for interactions of multiple simultaneous failures or implementation-specific malformed numeric lexemes is outside the profile.
