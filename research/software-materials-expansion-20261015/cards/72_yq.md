# 72_yq yq 多文档配置更新与可读输出兼容

- 路线：M5；优先级：`scope_probe`。素材候选，未构题/构建/运行/校准。
- 固定源码：`mikefarah/yq@a814ff5166040ec745a96bddd79ee31c3a548e83`；源码哈希/清单见 `../sources/72_yq/manifest.json`。
- 完整候选范围：完整限定工作流：多文档 YAML 读入→路径/递归选择→上下文相关赋值/删除/合并→注释/anchor/style 输出→原位文件更新或 stdout；具体表达式子集先锁定。
- 原题锚点：`git_rewrite_in_zig`, `libexpat_x86_assembly`；仅借难度机制，不承诺同等运行难度。
- 已有能力：已有可写/只读 context、相对赋值按子节点反向更新、YAML anchor map 与 leading-content 处理；不是基本 YAML 读写。
- 拟议缺口：拟构造行为兼容实现，非上游功能缺失；必须先确认成熟 YAML/表达式库或合法工具组合是否足够。

## 三类工作负载/工作流

- 多文档选择与缺失节点创建/相对更新
- anchor/alias/merge-key 与递归更新顺序
- 注释、标量 tag/style、非法表达式下 stdout/原位文件效果

- 最强正常基线：成熟 YAML AST 和表达式/查询库，允许合法工具组合；不得事后禁第三方 parser 维持难度。上游白空格只对已承诺部分精确比较。
- 首探/否证：先固定 SHA 的表达式语义/格式合同与文件副作用，跑多操作完整旅程差分；薄封装通过即换范围，不靠无依据字节保真要求加难。
- 正确性 oracle：冻结 yq+独立解析后树/alias 验证+对已承诺格式的精确文本；比较原位文件前后、退出码和错误；原生 assign scenarios 加新组合。
- 后续结构假设 1：若 AST 库不覆盖全合同，统一选择上下文、node identity/alias 与 children-first 变更的语义。
- 后续结构假设 2：若 parser+formatter 仍不足，协同 encoder、document metadata 和更新后 style/comment 保留；跨多文档验证。
- 离线：固定 Go 版本、go.mod/go.sum module cache；YAML v4 rc 等依赖预置并锁定；只取得片段。
- 许可观察：根 MIT 已存；Go 依赖及文档再分发另审。
- 平台风险：主要差异是文件系统/换行/时间和整数处理，不将 ARM 运行视为自动等价；固定 Linux 语义。
