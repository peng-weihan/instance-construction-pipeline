# 59_re2 RE2 受限缓存下批量正则匹配与捕获

- 路线：M3；优先级：`hold_until_baseline`。素材候选，未构题/构建/运行/校准。
- 固定源码：`google/re2@2da0056814cf180480a19f5cf811e7e1c054bf6d`；源码哈希/清单见 `../sources/59_re2/manifest.json`。
- 完整候选范围：正则编译→前缀/引擎选择→DFA 缓存/回退→捕获输出；保持指定 RE2 语法、first/longest 和内存预算。
- 原题锚点：`regex_automata_repair`, `integer_compression_codec`；仅借难度机制，不承诺同等运行难度。
- 已有能力：已有 DFA、one-pass、bitstate、NFA 选择及内存不足回退；匹配不需要位置时也有专门快路径。
- 拟议缺口：未证实缺口：合理 max_mem、编译复用及现有引擎后，工作集变动/多线程缓存是否仍有实质成本。

## 三类工作负载/工作流

- 短锚定少捕获：编译复用与 fast engine
- 长非锚定复杂 alternation：DFA 缓存与回退
- 共享 pattern 多线程/缓存压力：命中与锁/内存

- 最强正常基线：Release、正常 max_mem、编译对象复用、合适 anchor/捕获 API；尊重语义而不强制 NFA 或禁用缓存造弱基线。
- 首探/否证：扫合法 memory budget、线程和复用条件；同时测 compile/match、RSS 与尾延迟；配置足够或安全保证需削弱才能提速则撤销。
- 正确性 oracle：冻结上游+小规模穷举参考，逐项比较 match/span/captures 与错误；原生 DFA memory/multithread tests 和搜索差分测试。
- 测量计划：固定硬件/CPU/内存/存储与 seed，分离准备/实现执行；交错重复测正确结果的时间、RSS/分配及特定资源，记录噪声与跨 seed 泛化。奖励上下端点均未测；上游宣传倍率不是本题收益。
- 后续结构假设 1：强配置后若共享缓存构建/清空仍成为热点，研究状态生命周期与同步粒度。
- 后续结构假设 2：强配置后若重复 fallback 转换/扫描仍有成本，研究引擎选择和前缀处理，保留线性时间与捕获顺序。
- 离线：C++、Abseil、测试/benchmark 依赖预置；PCRE 仅选定交集参考，不能当全部 RE2 语义 oracle。
- 许可观察：根 BSD 风格许可已存，完整依赖许可未审计。
- 平台风险：x86/ARM 原子/缓存与字节扫描差异，分平台测；栈和内存上限保持一致。
