Existing Jinja customization, HTTPX, anyio and normal Python libraries are available offline.

An OpenAPI operation with one concrete successful response (`200` or `201`) of media type `application/x-ndjson` describes **one record**, not an array. Support a referenced object model (including its enum properties) and integer records. In this task, error responses have no body schema, and streaming operations have exactly one successful media type. Other OpenAPI capabilities retain their existing behavior. The fixture in `public/stream-contract.json` is the frozen integration workload; source parser/template unit tests also run. This is a generator feature, so do not hardcode the fixture's identifiers.

Generate `stream(..., client=..., **existing_endpoint_arguments)` and `asyncio_stream(...)` in each streaming endpoint module. They are synchronous/asynchronous context managers yielding an `Iterator[Record]` / `AsyncIterator[Record]`, with resolvable annotations for the actual generated record type. The async function is used with `async with`, without an extra `await`. Existing nonstreaming endpoints keep their regular APIs; streaming endpoints need not expose buffered `sync`/`asyncio` APIs.

Constructing a context does no HTTP request. Entering it opens one streamed response but consumes no successful-response bytes. Each iteration consumes only enough chunks to deliver the next record; HTTPX's normal chunk granularity applies. Decode UTF-8 across arbitrary byte splits, support CRLF and LF, skip whitespace-only lines, and parse a final record without a newline. Return generated models/enums through the generator's usual conversion conventions. Do not buffer the complete successful response. A public developer probe is `python public/smoke.py`.

The response is owned by the streaming context, including contexts that are entered but never iterated. Close it exactly once on exhaustion, early exit, malformed JSON, a consumer exception, or async task cancellation while waiting for another chunk. Preserve the original parse/consumer/cancellation exception. Never close or reenter the supplied HTTPX client. It must remain usable for ordinary requests afterward. Both manually injected and lazily created HTTPX clients are supported.

Check the response status before yielding records. A status other than the documented success raises the generated `errors.UnexpectedStatus`, with the received status and full error body, even if `raise_on_unexpected_status=False`. A successful response with an incompatible/missing media type raises `ValueError` before reading bytes. Compare the media type case-insensitively, ignoring parameters; NDJSON is UTF-8. All these paths release the response.

Resolve OpenAPI security inheritance: omitted operation `security` inherits document security; `security: []` explicitly makes the request anonymous; a nonempty OR list containing `{}` permits a plain `Client`. Required security has an `AuthenticatedClient` signature. Optional security keeps configured authentication when an authenticated client is supplied. Explicitly anonymous operations accept either client type and suppress both the configured authentication header and HTTPX default authentication **for that request**, after defaults have been merged. Do not modify shared headers/auth settings or other client state. Preserve unrelated default headers. Apply anonymous override to ordinary endpoints too.

The anonymous streaming POST accepts distinct JSON and multipart model bodies using the existing generated model APIs. Reuse normal `_get_kwargs`/body encoding: JSON preserves fields; multipart preserves the text field and each repeated file part, filenames, bytes and content types. A required request body remains required when multiple media types are present. The interaction matters: anonymous header suppression must preserve body Content-Type (including multipart boundary) and shared client reuse. Existing upstream multipart support is available and should be retained.
