# 软工任务难度分析范围

本轮问题：从原版 EdgeBench 的真实交付范围中提取可迁移的难度机制，形成能交给作者构造的新题规格。

范围为原题合同、原生产品目标、既有候选差距与新蓝图。采用任务合同层的定向深读，不声称覆盖各上游完整仓库。分析沿用当前工作区 Markdown 研究报告格式；既有题包、评分、轨迹和运行队列保持原版本。

分析分工：原版证据与反例；候选实际剩余工作和测量缺口；三个新交付范围蓝图。主分析负责难度机制、任务构造方法、证据核对与最终综合。各证据草稿完成后再合并。

叙事顺序：原题交付范围 → 结构性难度 → 当前小样差距 → 新产品范围 → 强基线与长程标定。

报告回答：

1. 求解者实际需要交付什么，starter 已经做了什么？
2. 扩大哪种需求会带来新的实现/诊断工作，为什么？
3. 单项能力完成后，哪些组合场景仍需集成？
4. 正常库、完整重解析或配置调参是否已经满足合同？
5. 早、中、晚阶段有哪些可保存、可重放的实际成果？这些阶段为工作顺序假设，不预言耗时。
6. 怎样用独立判据和冻结曲线推翻难度假设？
