# 交叉核验与交付检查

本记录针对 2026-10-14 的研究快照，范围为资料获取、静态源码分析和研究产物检查。

| 核验对象 | 方法与预期 |
|---|---|
| 官方全量与公开子集 | 从论文 Table 7 提取 134 个唯一 ID，与 HF 的 51 个唯一 ID 精确匹配；复核六类计数 |
| 机制分类 | 51 个任务定义逐题阅读；七个主类合计 51；各主类计数与 CSV 一致，保留次标签 |
| 成绩汇总 | 固定官方 README，提取 51 题 × 5 模型 × 6 时点；缺失为空，保留汇总值性质 |
| 文件来源 | 两个官方仓库固定 commit；五篇 PDF 验证文件头并记录版本、SHA256；六个 HF LFS 资产对照 Git 指针核对字节数和 SHA256 |
| 本地参考复制 | 比较源目录和副本全部工作树条目内容、符号链接目标、权限；排除可变 `.git` 内部文件；记录 HEAD 和状态 |
| 运行契约 | 从 TaskSpec、评测、parser、选择、归一化、实验配置交叉核对公开任务；区分配置值与 CLI 默认值 |
| 参考工厂 | 从当前源码、原始规约和历史 summary 交叉核对阶段语义；区分 NL2Repo accepted、DeepSWE L2、ProgramBench R1/R2/R3 |
| 蓝图 | JSON 可解析；三题族 ID 唯一，灵感任务均存在于论文索引；仅有论文信息的 stream_processing_engine 明确标注；设计提案不冒充 SForge task JSON |
| 报告与入口 | 检查本地 Markdown 链接目标存在；核对统计、来源范围与实际产物 |

核心判断经两侧接口复核：SWE Factory 输出构造与红绿证据，SForge 输入 Work/Judge 与提交评分契约。两者之间仍需导出器，尤其要处理 patch 删除语义、主动/自动评测时的重新捕获、严格评分映射和独立终评。

本次未执行参考工厂测试、Docker、真实模型或新实例试产；历史示例只作为历史证据。不存在本次已通过的长时任务校准结果。源码逐文件阅读范围和依据分别列于模块分析笔记，不以全仓库阅读覆盖作为结论。

脚本执行结果与结构检查汇总保存为 [artifact_validation.json](../artifact_validation.json)。
